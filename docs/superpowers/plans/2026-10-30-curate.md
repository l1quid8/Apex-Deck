# `/curate` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this group chat, "subagent" means the named bot below, handed the task by @mention. Don't spawn private helpers.

**Goal:** Add `/curate` and `/curate undo`, so a bot can hide old messages from every bot without deleting anything, and bots can still look up the exact originals.

**Architecture:** `Room` keeps a list of curations and leaves hidden messages out of what it sends, replacing each run with one short line. All bots get history through one function, so that single change reaches them all. Lookups use a plain journal file in the folder every bot may already read, so no new tool, command or permission is needed.

**Tech Stack:** Rust (`apex-core`, `apex-host`, `apex-daemon`), TypeScript and React (`src/`), `cargo test`, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-30-curate-design.md`

## Global Constraints

- A thread that never used `/curate` gets byte-identical prompts, and `/compact` behaves as it does today.
- Nothing in this work deletes or edits a transcript message.
- User-facing strings come verbatim from the "All the wording" table in `mockups/curate-v1.html`, plus the two this plan adds: the refusal in Task 5 and "Run /curate again…" in Task 7.
- Constants: newest protected `KEEP_NEWEST = 20`, long-message excerpt `HEAD_CHARS = 120` + `TAIL_CHARS = 120`, whole Human messages up to `HUMAN_CHARS = 2_000`, recent context `CONTEXT_CHARS = 12_000`, complete request cap `REQUEST_CHARS = 64_000` including `OUTPUT_CHARS = 4_000` reserved for output, digest ceiling `DIGEST_CHARS = 60_000`, reason cap `REASON_CHARS = 160`, journal line `JOURNAL_LINE_CHARS = 1_000`, journal size `JOURNAL_BYTES = 9 MiB`.
- Journal path: `<data>/attachments/<room>/deck-journal/chat.md`, mode 0600, replaced atomically.
- **The journal is current or gone,** and a prompt names it only while it's there. See Task 4.
- The curator has no tools. It's built the way talk-only `/compact` builds its bot, never with `build_without_tools`, which leaves CLI bots their tools.
- `/curate` runs in desktop Work threads only.
- No new crate or npm dependencies.
- Per `AGENTS.md`: run `git status` before switching branches, start dev builds only from the main folder with `APEX_DECK_DATA_DIR="$HOME/Library/Application Support/dev.apexdeck.app" npm run desktop:dev`, require `npx tsc --noEmit` to pass before merging, and delete the branch after an authorized merge.
- Inside a Deck pane, run socket-using tests with `TMPDIR=/tmp`.

## Review Focus

1. **A very long chat, or one enormous message.** The curator's prompt stays under the cap, and running `/curate` again moves on even if the last run hid nothing. Tests in Task 2.
2. **`/curate` or `/curate undo` typed while bots are working.** It waits its turn and never overlaps a running turn. Tests in Tasks 5 and 6.
3. **Retry or Revert across a curation.** The hidden list and the journal both go back, and no cut message stays readable. If the journal can't be rewritten it's taken away, and if that fails too the Human is told. Tests in Task 4.
4. **The journal can't be written (disk full, folder blocked).** During `/curate`: nothing is hidden, no model is called, and the reason is shown. Later: bots are told the text can't be read, and are never pointed at a missing file. Tests in Tasks 4 and 5.
5. **Old or odd saved data.** An old thread opens unchanged, and a curation that doesn't fit the transcript is dropped rather than causing a crash or hiding the wrong messages. Tests in Task 1.
6. **A message the curator could only partly see.** The digest never makes a Human message look shorter than it is, and a long bot message shows its start and end. Tests in Task 2.
7. **One very long line.** Every word of it can be reached with line-based file tools. Tests in Task 4.

```rust
but a model won't look for something it doesn't know is there. \

Keep what the human asked for and still wants, decisions, open questions, and exact values still in use. \
Use the recent messages to judge what still matters. \

If you are unsure, keep it. You have no tools. Reply with one JSON object and nothing else: \
```

- [x] **Step 3: Implement `Room::curate`**

Model it on `compact` (`room.rs:844`), with these differences:

1. Eligible: `compacted_upto()..len.saturating_sub(KEEP_NEWEST)`, minus hidden numbers, `response_pin_parts` numbers and anything `offerable` refuses. If empty, return the error above before any model call.
2. Candidates: the eligible numbers `>= curate_from`, or all of them if none are left.
3. Build the complete system text `CURATE_SYSTEM + &pinned_section(&self.pins)` first. Subtract its character count and `OUTPUT_CHARS` from `REQUEST_CHARS`, then pass the remaining budget (at most `DIGEST_CHARS`) to `digest`. Count headings, omission notices and role framing inside that budget. Refuse before `TurnStarted` or a model call if protected system/pin material leaves no room for recent context and at least one complete candidate. Never clip pins. This is a character bound, not a provider token-window guarantee. `TurnRequest` uses that system, one user digest turn, `access: Some(Access::Read)`, `plan: false`, `cwd: None`.
4. After `TurnStarted`, emit `Activity` with `CURATE_WORKING`. Drop `Progress::Text` from the progress sink, because the reply is a list for Deck, not a message.
5. Emit `RoomEvent::ParticipantIdle { id }` on every exit after `TurnStarted`. Phones clear their working state from it, with no phone change needed.
6. `parse_picks` failure returns `Err(format!("{name} did not give a usable list"))`.
7. On a usable reply, set `curate_from` to one past the last offered number, and `unchecked` to the candidates past it. A stop or a failure leaves `curate_from` alone.
8. If anything was picked, push a `Curation` with `at = transcript.len()`, then emit `CurationsChanged`.
9. `clear()` sets `curate_from` to 0, and `rewind(upto)` sets it to `curate_from.min(upto)`. A new summary needs nothing, because eligible numbers already start there.

### Task 4: The journal file

**Files:**
- Create: `crates/apex-host/src/journal.rs`
- Modify: `crates/apex-core/src/curation.rs`, `crates/apex-core/src/room.rs`, `crates/apex-core/src/lib.rs`, `crates/apex-host/src/lib.rs`, `crates/apex-host/src/host.rs:65,1066,1110,2475,2959,3604`
- Test: `crates/apex-adapters/src/api_tools/files.rs:473`

**The rule: the journal is current or gone.** Bots rely on it only for what isn't in their prompt, which is hidden messages and whatever a summary replaced. Anything newer is in front of them. So the file needs to be right, not up to the minute, and its first line says how far it goes.

| State at a sync | What happens | What bots are told |
|---|---|---|
| No curation stands | The file is removed | Nothing |
| A curation stands and the write works | The file is replaced | The path |
| The write fails, or the text is over `JOURNAL_BYTES` | The old file is removed (`Gone`) | The text can't be read right now |
| The write fails and removal fails too | `Stale`, returned as an error so the Human sees it | The text can't be read right now |

`JOURNAL_BYTES` sits under the API `grep` tool's 10 MiB limit, so a journal is never silently skipped. The longest real thread today is about 0.47 MB, so this is a clear stop for an unusual chat, not a limit anyone should meet.

**Interfaces:**
- Consumes: `stands` (Task 1), `write_synced` and `sync_directory` (`storage.rs:10,26`).
- Produces, in `curation.rs`:
  ```rust

  pub const JOURNAL_BYTES: usize = 9 * 1024 * 1024;
  pub fn journal_text(transcript: &[Message], roster: &[ParticipantConfig]) -> String
  /// `None` when a curation stands but the file isn't there.
  pub fn journal_section(path: Option<&str>) -> String
  ```

- Produces, on `Room`: `pub fn set_journal_path(&mut self, path: Option<String>)`, held in a private unsaved shared hint. `journal_path_handle()` exposes its `Arc<Mutex<Option<String>>>` so synchronous replacement imports can invalidate the prompt hint without taking the async transcript lock.
- Produces, on `RoomHandle`: `pub(crate) journal: Option<PathBuf>`, `None` for talk-only rooms.
- Produces, in `journal.rs`:
  ```rust

  ```

Journal encoding is versioned and reversible. The header names the coverage and explains the format. Each message starts `#<seq> · <speaker>`. Its text is a sequence of `| <JSON string>` records; concatenate the decoded strings to recover the exact original, including CRLF, trailing newlines, literal `⏎` and Unicode. Bound each encoded record to `JOURNAL_LINE_CHARS + 4` characters (below the API reader's 2,000-character limit), preferring a space near the boundary. Between chunks add `? <JSON string>` search-only overlap records with up to 64 original characters from either side. Ignore `?` records when reconstructing. These make literal searches of up to 64 characters across a chunk boundary work; longer patterns may need ranged reads. JSON escaping applies to content, never a global replace of a sentinel.

`journal_section(Some(path))` explains hidden ranges, the exact-text file and its coverage, the `|` JSON chunks and `?` search-only overlaps, and says to search before relying on hidden material. `journal_section(None)` says: "Their text can't be read right now, so never guess what a hidden message said. Tell the human if you need one."
