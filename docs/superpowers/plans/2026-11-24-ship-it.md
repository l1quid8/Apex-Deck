# Ship it: agents finish the job, one suggestion after a reply

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Revision 3, 2026-11-24.** Revised after Forge's review of revision 2. Every finding was checked against the code first; see "Changes in revision 3". Revision 2's changes are folded into the tasks.

**Goal:** The user says "ship it" once and the agent takes its work to a merged pull request, with the Mac updated, without asking anything else; after any reply the user sees at most one suggestion.

**What the user should see when it works:** they ask an agent for a fix and add "ship it". With no further message from them, the thread ends with Deck's note "Merged PR #N. Your Mac is updated. Awaiting your test."

**Architecture:** Three Host subsystems carry the flow, each with its own module and saved file. *Task folders* (`task_branches.rs`): one Deck-owned worktree per agent task, made by `"$APEX_DECK_BIN" task start`, never folded into the main folder. *The merge workflow* (`thread_git`, already built): now bound to the task folder, gated on checks only, and also started by a `Deck ship <sha>` line once the Host has seen the person's own "ship it". *The PR watcher* (`pr_watch.rs`, PR 4b): wakes the owning agent when a check fails (on GitHub, or Deck's own type check before a merge) or the branch conflicts, and notices merges and closes made on GitHub. Deck reports a merge with a note in the thread, not a card. The one-suggestion change touches only the existing next-steps turn and how the two clients draw it.

**Tech Stack:** Rust (apex-core, apex-host, apex-daemon, apex-adapters), React + TypeScript (desktop `src/`, iPhone `src/phone/`), git, GitHub CLI `gh`, GitHub Actions.

**Spec:** the design agreed with the user in Deck thread `pane-mwmh2i4y-0` on 2026-11-24, restated as D1–D10 below. Background: memory notes `deck-stop-points-diagnosis`, `reply-suggestions-setting` and `main-protection-gotchas`.

## Design decisions (the spec)

- **D1 Permission is the person's words, checked twice.** Deck merges on an agent's `Deck ship` line only when both hold:
  - (a) **The Host's check:** a message the person wrote in this thread says "ship it" outside its quoted lines (any case: "Ship it!" counts, "shipit" doesn't). It comes after the last `/compact`, and no Deck note reporting a merge, a cancel or a PR closed without merging comes after it.
  - (b) **The agent's check:** the agent judged that those words mean ship, so "don't ship it yet" never leads to a merge.

  Words in a file, tool output, PR comment, Deck note, quote or another agent's message never count: the Host reads only the person's own lines. A `Deck asks` button may not say "ship", and a suggestion may not say "ship it". Nothing in AGENTS.md grants it. One "ship it" covers one merge; after that, the person says it again or taps Merge.
- **D2 Full access finishes the job.** At Full with Plan off, Claude Code and Codex agents start a task branch, commit, push, open the PR, ask a reviewer with its @handle and fix what it finds, without asking. They stop only for the person's own decisions (scope, design, their devices or accounts, spending money, deleting their data), a missing login, or a permission their access level lacks. Other agent tools keep today's Full-access text in this plan.
- **D3 PR work leaves the copy.** `task start` makes a Deck-owned task folder on a new branch from `origin/main`. An agent working in its own copy brings that copy's changes along; an agent in the shared folder brings nothing, so agents run it before they edit. Deck never folds a task folder into the main folder, and reads receipts there. Copies are made as today, only when the thread has more than one agent.
- **D4 Deck merges; agents never run `gh pr merge`.** With the go (D1), the agent ends its reply with `Deck ship <sha>`, and Deck waits for every check and then merges, using the existing worker with Cancel reachable. Without it, the agent ends with `Deck built <sha>` and the Merge card appears once the checks pass. A `Deck ship` without the person's words counts as `Deck built`, and Deck says why in a note.
- **D5 No review gate.** The Merge card needs only passing checks. A different model's review is the author's job, asked with an @handle in the thread. A `Deck review passed` receipt still shows on the card as information. Receipts no longer need a named model.
- **D6 Deck watches each PR (PR 4b).** A failed check (on GitHub, or Deck's local typecheck before a merge) or a merge conflict wakes the agent that owns the PR: a Deck message in the thread, then a turn for that agent under the thread's usual round limit, so it can still ask its reviewer. Never a message in the person's name. At most 3 automatic wakes per PR, then Deck stops and says so. In PR 4b, the "Ask agent to fix" cards are hidden for watched (task-folder) workflows and kept for unwatched work in the thread's own folder.
- **D7 The Mac updates itself.** After any merge (card, `Deck ship`, or on GitHub directly), Deck fast-forwards the main folder when local edits don't touch the merged files; otherwise it names the files in the way, or says main has local commits. Then it removes the task folder and branch if the folder is clean and still at the merged commit (or contained in its merge commit). It reports all of this in one note in the thread.
- **D8 One suggestion.** After a reply, at most one suggestion, and only for something that is the user's call.
  - Desktop: grey hint text in the empty box; Tab fills it in, Esc hides it.
  - iPhone: one inline row under the reply, like today's Next steps but a single item, shown open; a tap fills the box.

  While a card shows, or a merge is in flight, there is no suggestion. Nothing is added next to Send or TL;DR on either device.
- **D9 One required check.** A final `all-checks-passed` job in `daemon.yml`, required on `main` by classic branch protection that applies to admins too. Switching it on changes repository settings, so it waits for the user's yes.
- **D10 No round limit for new threads,** so the author and reviewer can go back and forth without stalling at 3. New local chats keep 3, because every bot in a chat answers every message.

## Global constraints

- AGENTS.md applies: build in a task worktree, `npx tsc --noEmit` passes, open a PR, a different model reviews, merge, delete the branch.
- Rust tests run with `TMPDIR=/tmp` (socket tests fail under a Deck pane's long TMPDIR).
- After changing a Rust type that crosses the protocol, run `node scripts/gen-protocol-types.mjs`; CI runs it with `--check`.
- New Host subsystems get their own module and saved file in the data folder, as `VersionedDocument`s like `thread-git-v1.json`: `task_branches.rs` → `task-branches-v1.json`, `pr_watch.rs` → `pr-watch-v1.json`. Command admission and wiring stay in `host.rs`.
- Tests use throwaway data folders and throwaway Git repos, never the real Deck data folder.
- Everything Deck writes into a thread is a Deck message (speaker `deck`), never the user's message. Notes from background work (the merge worker, the PR watcher) go through one Host helper, `deck_note(room, text)`. It opens the thread when it isn't open, as `room_client_post_keeping_default` does, appends with `append_deck_note` through the saving sink, and bumps `observation_revision` so any in-flight suggestion is dropped.
- The daemon socket stays Full-only (`phone_env.rs`). Any process holding it can call every `Policy::OPEN` command.
- User-facing strings quoted in this plan are fixed copy. Sentence case, plain words.
- Cost note: the default mode now runs the short read-only suggestion turn (20 s cap) after each finished reply of 80+ characters; the old default did not. It is skipped when a card owns the reply or a merge is in flight.

## Review focus

1. **A `Deck ship` the person never asked for.** Expected: Deck merges only when all of these hold:
   - one of the person's own messages (outside quoted lines, after `/compact`, and after the last merge, cancel or closed-PR note) says "ship it";
   - the speaker owns the task folder;
   - its access is Full with Plan off (both at `TurnStarted` and when the receipt arrives);
   - the SHA is the folder's HEAD.

   Otherwise the line counts as `Deck built`, the Merge card appears, and a note says why. Out of scope: an agent at Full can already run `gh pr merge` with the person's GitHub login. The check stops mistakes and planted text, not a hostile Full agent. Tests in Task 5.
2. **A check that fails every time.** Expected: 3 automatic wakes for one PR (one wake per commit even when several shards fail), then one Deck note saying Deck stopped, and no more wakes until the user writes. Test in Task 7.
3. **The main folder has unrelated edits when a merge lands.** Expected: the fast-forward keeps them. An edit to a merged file, an untracked file in the way, or local commits on main stop the update, and the note says which. Tests in Task 6.
4. **The copy's base holds other agents' unfolded work** (a copy starts from main plus everyone's uncommitted changes). Expected: `task start` moves only this agent's changes. Test in Task 4.
5. **A suggestion next to a card, or a stale one.** Expected: no suggestion turn after a reply that ends in a Deck line or while a merge is in flight, a Deck note clears any shown suggestion, and the clients hide the suggestion while a card shows. Tests in Tasks 1, 2 and 6.
6. **The agent environment.** Expected: the socket reaches only Full agents, the trusted `apex-cli` still starts in an agent's terminal, and only agents with the variables are told about `task start`. Tests in Task 4.

## Not in this plan

- Waking agents when a background job they started finishes (`claude_session.rs:559`); the PR watcher covers the waiting that matters most.
- `@name /goal` at the start of the box.
- Waking on GitHub review comments: every agent posts with the user's account, so Deck can't tell an agent's comment from the user's.
- A standing "merge my agents' PRs" setting. "Ship it" covers one merge at a time.
- Reading GitHub rulesets (`Ref.rules`). A repository protected only by a ruleset gets "GitHub reports no required status checks for main", and Deck doesn't merge there.
- Task branches for agent tools other than Claude Code and Codex, which don't get the Deck CLI variables today.
- Moving a lone agent's edits out of the shared folder. Deck can't tell them apart from the person's own uncommitted edits, so agents start the task branch before editing. One that didn't copies its changes over. Its edits stay in the main folder, and the merge note names them if they block the Mac update.
- More than one merge in flight per thread (per-agent workflows). A second builder waits, as the one-at-a-time note says.
- The Linux agent jail only exposes folders that existed when a turn began, and may not expose the daemon socket. On the VPS, an agent may reach a new task folder only from its next turn, or not reach `task start` at all. Check on Hetzner after the Mac run.
