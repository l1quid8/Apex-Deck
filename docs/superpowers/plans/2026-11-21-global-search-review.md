# Search Deck review of revision 1

Keep the per-machine search module and the three independently cancellable lanes. Start with fixture-driven backend work once the following changes are incorporated. The extended mockup is the desktop design gate. The plan header and the chat handoff currently give different start conditions.

1. **Prove admission at the entry point.** The device table in `crates/apex-daemon/src/authority.rs` handles paired-device scope. That alone does not establish caller provenance for local commands. Require a trusted human client at admission, deny agent tools and personal workers before touching stores, and cover full unrestricted versus thread-limited devices in the authority matrix. Bind cancellation state to the authenticated client and window. Report which callers the tests actually covered.
2. **Resolve a durable target before using position.** Two messages can contain the same words. Prefer room/machine plus a stable message identifier, then a validated sequence fallback. Fail gracefully on ambiguous, deleted or moved targets. Steps can also shift or be dropped. Resolve them by saved key within the verified reply. Test duplicate phrases and live curation between search and click.
3. **Search retained history.** In `crates/apex-core/src/work_steps.rs`, output and detail are cut, and fitting a reply can discard older steps. Describe results as covering saved history. Parse logical records before applying the word/phrase matcher, or prove a prefilter cannot reject a true match across JSON escapes, case or separated words. Evaluate file lines with the same stated semantics. The existing git helper accepts one literal.
4. **Bound work and prove freshness.** Scope the benchmark to end-to-end query latency with concurrent windows and cached working sets exceeding 64 MiB. Measure peak resident memory separately from cache size. Check store generation/identity across each read, handle same-size replacements, and recheck lifecycle visibility on cache hits. Test supersession, disconnect and deadline during subprocess execution, bounded queue size, child reaping and stale-response suppression.
5. **Constrain filesystem scope on every backend.** Use registered project identifiers, resolve current canonical roots, prevent symlink escapes, and apply the same secret-file exclusions to Git and non-Git scans. Git ignore rules alone do not hide tracked files. Test tracked env files, nested checkouts, missing folders, binary data and Windows path parsing. Disclose timeout, hit caps and skipped roots separately.
6. **Define completeness across machines and pages.** A locally loaded name list can omit remote names. Specify coverage for projects, agents and archived/trashed thread names even when their messages do not match. Include machine IDs in merge and navigation keys. Distinguish known counts from capped counts and implement a scoped continuation or narrower search for overflow. Task 2 can only measure steps after a representative step reader exists. Keep real VPS/Windows performance and native phone acceptance pending until measured.
