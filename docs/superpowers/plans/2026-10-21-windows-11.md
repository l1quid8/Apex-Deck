# Windows 11 port plan (2026-10-21)

Goal: Apex Deck runs natively on Windows 11: the app, its daemon, and the bots
all run on Windows itself, with no WSL. It ships as a signed installer, and
Mac behaviour does not change.

All of this work happens on one branch, `feat/windows-11`, in its own worktree
at `~/Downloads/apex-deck-worktrees/windows-11`. The branch started from local
main at `45f709f`. It is pushed to GitHub after each step so the Windows CI job
can run. Main is never pushed from here, and merging into main needs the
Human's OK.

## Where we are

- `apex-core`, `apex-adapters` and `apex-host` already have `cfg(not(unix))`
  fallbacks in most places.
- `apex-daemon` has none and does not compile for Windows, failing in about
  25 places.
- The Electron shell depends on a Unix socket (`daemon.sock`) and on the macOS
  LaunchAgent.
- No CI job builds for Windows, so nothing catches regressions. This Mac can't
  compile the Windows target either, because `ring` and `aws-lc-sys` need
  Microsoft's C toolchain to build.

## Design

The architecture stays the same. Only the connection between the app and the
daemon, and the parts that talk to the operating system, change.

```
Electron app ──(local pipe)──> apex-daemon.exe ──> bot CLIs (claude.exe, codex.cmd, gemini.cmd)
   today: daemon.sock (Unix socket)     Windows: \\.\pipe\apex-deck-<user>-<hash>
```

1. **Local connection.** A named pipe that only the current Windows user can
   open. Node's `net.createConnection` already accepts `\\.\pipe\…` paths, so
   `desktop/link.mjs` and `desktop/sidecar.mjs` only need a different path.
   The daemon uses `tokio::net::windows::named_pipe`, and the pipe's access
   rules replace the Unix `geteuid` peer check. A small `ipc` module in
   `apex-daemon` hides the difference behind `listen(path)` and
   `connect(path)`.
2. **Stopping bots.** Each bot's process tree goes into a Job Object that kills
   every process when the job closes. This replaces process groups and
   `killpg` in `apex-adapters/src/owned_process.rs` and
   `apex-host/src/personal_worker/process.rs`.
3. **Data folder.** `%APPDATA%\Apex Deck`, through a new `Windows` variant of
   the `Os` enum in `crates/apex-daemon/src/paths.rs`.
4. **Secrets.** Windows Credential Manager, through `keyring`'s
   `windows-native` feature, which `apex-host/Cargo.toml` already enables.
   `apex-adapters/src/keys.rs` gets a Windows branch next to the Keychain
   branch. `%APPDATA%` is private to each user, so the files that are 0600 on
   Unix need no extra access rules.
5. **Finding bot CLIs.** Search the process's own PATH instead of asking a
   login shell. Prefer `.exe`, then `.cmd`; Rust 1.77 and later escape `.cmd`
   arguments safely.
6. **Shell for API bots** (`api_tools/shell.rs`). Use Git Bash when it is
   installed, since Claude Code on Windows needs it anyway; otherwise use
   `powershell.exe`. The bot prompt names the shell in use.
7. **Daemon at log on.** A Task Scheduler "at log on" task, created with
   `schtasks` and running as the user. It is always registered on installed
   builds, the same rule the LaunchAgent follows after the pairing upgrade
   (9b36e35).
8. **Codex approval hook.** Moves to a named pipe in M5. Until then, Windows
   uses the existing inventory fallback, which works but is slower.
9. **Turned off in Windows v1:**
   - The Phone tab, which needs the iOS Simulator.
   - Voice, which needs MLX or the Linux helper.
   - The model-gateway sandbox, because `sandbox-exec` exists only on macOS.
     Windows shows a "not sandboxed" note instead.
10. **Machines and installer.** x64 first, arm64 later. The installer is NSIS
    through electron-builder, signed with Azure Trusted Signing
    (`win.azureSignOptions`). It is built on GitHub's `windows-latest`,
    because Windows binaries need Windows to compile.

## Branch and worktree

```bash
cd ~/Downloads/apex-deck && git status        # leave others' unsaved work exactly as it is
git worktree list && git rev-parse main
git worktree add --detach ~/Downloads/apex-deck-worktrees/windows-11 main
cd ~/Downloads/apex-deck-worktrees/windows-11 && git switch -c feat/windows-11
ln -s ~/Downloads/apex-deck/node_modules node_modules
export CARGO_TARGET_DIR=~/Downloads/apex-deck-worktrees/.pair-target   # shared worktree cache
```

- In this folder, only run checks: `npx tsc --noEmit`, `npm test`, and
  `cargo test` on the Mac. Don't run `npm run desktop:dev` or build a DMG here;
  AGENTS.md still applies.
- If a step adds an npm package, run `npm ci` in this folder instead of using
  the symlink.
- Never run `git add -A`, because `node_modules` is a symlink.
- Keep personal paths out of commits. Write `~/` or `%APPDATA%` instead.
- Run `git push -u origin feat/windows-11` after each finished step.
  `daemon.yml` runs on every push, so Linux x86_64, Linux arm64, macOS and
  Windows are all tested.

## Keeping up with main

- At the start of each milestone, re-check `git worktree list` and
  `git rev-parse main`. Then run `git merge main` in the worktree, run the
  checks, and push.
- **Overlap with the pairing work.** `integrate/pairing-batch1` edits files
  that M1 and M3 also need: `serve.rs`, `pair_cli.rs`, `pair_commands.rs`,
  `desktop/main.mjs`, `launchAgent.mjs`, `sidecar.mjs` and `remoteSwitch.mjs`.
  M0 and the half of M1 that doesn't touch those files start now. The rest of
  M1, and M3's desktop startup work, wait until pairing is in main and main
  has been merged into this branch.

## Milestones

Gronk builds each milestone, and Null reviews it before the next one starts.
If Null builds a step, Jigga reviews it. Jigga integrates and pushes.

- **M0: Windows CI.**
  - Add a separate `test-windows` job on `windows-latest` to
    `.github/workflows/daemon.yml`, with `continue-on-error: true`. Keeping it
    separate means it can't block the Linux `build` job, which `needs: test`.
  - The job runs `cargo check --keep-going --all-targets` on the four tested
    crates, then the same `cargo test` line the other jobs run.
  - The Windows error list becomes the M1 checklist.
- **M1: the daemon builds and its tests pass on Windows.**
  - These parts start now:
    - `crates/apex-daemon/Cargo.toml`: `libc` on Unix only, `windows-sys` on
      Windows.
    - `signals.rs`: listen for the Windows `ctrl_c`, `ctrl_close` and
      `ctrl_shutdown` signals.
    - `files.rs`: apply the 0600 file mode on Unix only.
    - `paths.rs`: the `%APPDATA%` folder.
    - `gemini_usage.rs` and `grok_usage.rs` in `apex-adapters`: use the
      `HOME` → `USERPROFILE` fallback that `catalog.rs` already has.
    - `stdio.rs` and `local_call.rs`: move onto the `ipc` module.
    - Gate the tests that need symlinks or file modes.
  - After pairing lands: move `serve.rs`, `pair_cli.rs`, `pair_commands.rs`,
    `gateway_cli.rs`, `devices_cli.rs` and `phone_cli.rs` onto the `ipc`
    module. `pair_commands.rs` also uses `COMPUTERNAME` as the hostname on
    Windows.
  - Done when the Windows job passes. Then remove `continue-on-error`.
- **M2: bots run and stop on a real Windows PC.**
  - Job Objects for stopping bots.
  - CLI discovery in `apex-host/src/agents.rs`.
  - The shell for API bots.
  - `codex_server.rs`: run `sh -c` on Unix only.
  - `step_labels.rs`: unwrap `powershell -Command` and `cmd /C` so step
    labels read cleanly.
  - `personal_worker/browser.rs`: the usual Chrome and Edge install paths on
    Windows.
  - Done when a Claude, a Codex and a Gemini bot each answer in a room, and
    Stop leaves no processes behind (checked in Task Manager).
- **M3: the Electron app on Windows.**
  - `link.mjs` and `sidecar.mjs`: the pipe path and `apex-daemon.exe`.
  - `desktop/winLogonTask.mjs`, the Windows counterpart of
    `launchAgent.mjs`.
  - Windows wording, for example "Show in Explorer" instead of "Reveal in
    Finder".
  - The default window frame instead of `hiddenInset`.
  - One shared path helper in `src/` that splits on `/[\\/]/`.
  - Hide the Phone tab and voice controls where Windows doesn't support
    them.
  - Add the Node checks (`npm ci`, `npx tsc --noEmit`, `npm test`) to the
    Windows job.
  - Done when `npm run desktop:dev` runs on the Windows PC and the usual smoke
    test passes.
- **M4: signed installer.**
  - `electron-builder.yml`: a `win:` NSIS target, `extraResources` for
    `apex-daemon.exe`, and `azureSignOptions`.
  - `scripts/package-win.mjs`.
  - A CI job that builds, signs and uploads the installer as a build
    artifact. It publishes nothing.
  - The Human adds the Azure secrets to GitHub and approves an AGENTS.md line
    saying Windows installers are built by CI.
  - Done when the installer runs on a clean Windows 11 PC with no "unknown
    publisher" warning, and the app starts its daemon.
- **M5: remaining gaps.**
  - The Codex approval hook over a pipe (`codex_hook.rs`, and the POSIX
    quoting in `hook_command`).
  - An arm64 build.
  - Remote access from the phone to the Windows daemon.

## Merging into main

Merge only after the Human says so, and only after these checks:
- `npx tsc --noEmit` passes (AGENTS.md).
- `npm test` and `cargo test` pass on the Mac.
- The Windows job passes.
- Null has signed off.

Make the usual `Merge branch 'feat/windows-11'` commit. Afterwards, delete the
branch both locally and on GitHub, and remove the worktree.

## Needed from the Human

- A Windows 11 x64 PC for testing M2 to M4.
- An Azure Trusted Signing account. Its identity check takes a few days.
- Approval of the AGENTS.md line at M4.

## Verification

- Before every push, in the worktree, run `npx tsc --noEmit`, `npm test`, and
  `cargo test` on the Mac.
- On every push, the Linux and macOS jobs must stay green, which shows Mac
  behaviour hasn't changed. The Windows job may fail during M0 and M1, and
  must pass from the end of M1 on.
- From M2 on, on the Windows PC:
  - Install the app.
  - Add three bots and chat with them.
  - Press Stop and check Task Manager for leftover processes.
  - Restart the PC and confirm the daemon starts at log on.
  - Open a Windows folder as a project.
  - Try the terminal tab, which uses ConPTY.
  - Uninstall.
