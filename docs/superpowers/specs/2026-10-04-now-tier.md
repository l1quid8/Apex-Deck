# Now tier: spec

The 16 "Now" ideas from the 2026-10-04 feature and UX review of v0.3.0
(`main@95d753d`). Each idea was proposed from the code, checked by a separate
reviewer against the source, and drawn where a picture helps. Mockups and the
full ranked list (42 ideas, Now / Next / Later) are on the review canvas:
<https://claude.ai/artifact/Na5aRkN43eEkhwFtsnfSmH> (private to Tyler until
shared).

This document says **what** each change does and the exact copy. The plans in
`docs/superpowers/plans/2026-10-04-now-*.md` say **how**, task by task.

## Shared interfaces

These names are fixed across plans. A plan that needs one of them uses it
exactly as written here.

- **`ThreadStatus`** (stage 1, `src/types.ts`). What a thread reports to `App`
  through `onStatus`, replacing today's display string:
  ```ts
  export interface ThreadStatus {
    /** The muted words in the pane head when no flag shows, e.g. "2 bots · replying". */
    text: string;
    /** Display names of bots producing a reply right now (not counting ones stopped on a card). */
    replying: string[];
    /** Display names of bots stopped on an open approval card. */
    waiting: string[];
  }
  ```
  `App` keeps `threadStatus: Record<string, ThreadStatus>`. Stage 2 (2.5)
  changes how `text` is computed, never the shape.
- **`Workspace.hidden?: boolean`** (stage 1, `src/types.ts`). A workspace
  removed from the list. Missing means `false`.
- **`Signal.blocking?: boolean`** (stage 2, `src/attention.ts`). A flag that
  looking at the pane does not clear. Only open approvals set it.
- **`src/approvals.ts`** (stage 2). App-wide store of open approval cards fed by
  `src/hub.ts`, in the pattern of `src/plans.ts`. Stage 2 defines its exact
  types; stage 3 (3.1) reads it only through its exported functions.
- **Saved panes** (stage 4). `savedThreads` / `loadedThreads` in
  `src/closing.ts` generalise to `savedPanes` / `loadedPanes`, which also keep
  terminal descriptors `{ id, workspaceId, kind: "terminal", title, agent }`.
- **Rust wire changes**, each with a `crates/apex-core/tests/wire_format.rs`
  update: `McpCall.expires_at` (stage 2), `HopLimitReached.next` and a hop budget
  on `room_turn` (stage 3), `ProposedAction.risky` and `AllowedRule.allowed_at`
  (stage 5). New fields on saved structs use `#[serde(default)]` so older
  session files still load.

- New files differ from every existing file name by more than case.
- Commit on the stage's feature branch. Don't push and don't merge to `main`
  unless Tyler asks.

## Stage 1: safety

### 1.1 Removing a workspace never deletes its threads

Today the hover × on a workspace row calls `removeWorkspace`
(`src/App.tsx:302`), which runs `roomDelete` on every thread (deleting the saved
file) and unmounts every terminal (killing its process). No question, no undo,
and the tooltip says "closes its panes, keeps the folder".

- The row's × becomes a ⋯ button (`aria-label` "More for <name>") opening a
  menu: **Rename**, **Reveal in Finder**, separator, **Remove from list…** in
  danger text.
- Remove from list sets `hidden: true` on the workspace. It never calls
  `roomDelete`. Its terminals end; its threads stay saved and closed.
- It asks only when one of its terminals is working or waiting
  (`closeNeedsConfirm`) or one of its threads is replying or waiting on a card.
  - Title: "Remove <name> from the list?"
  - Body, built from the counts, e.g. "2 terminals are working and 1 is waiting
    for you. They end now. Its 4 threads stay saved and come back if you add the
    folder again." Omit clauses whose count is 0. If nothing is running, the
    body is just "Its 4 threads stay saved and come back if you add the folder
    again." (and with no question asked at all when nothing is running).
  - Buttons: Cancel (focused) and "Remove from list" (danger).
- After removing: toast "<name> removed." with **Undo** for `UNDO_MS`. Undo
  unhides the row and its threads. It cannot bring back terminals.
- Adding a folder whose path matches a hidden workspace unhides it instead of
  creating a second one.
- The rail foot shows a muted "Removed (n) · Show" line while any workspace is
  hidden. Show opens a small menu listing them; choosing one unhides it.
- Rename uses the existing `ThreadName` (double-click or F2), saved as
  `Workspace.name`. The row's `title` shows the path.
- Reveal in Finder uses the existing `openTarget(path, reveal = true)`.
- The active workspace row drops its green marker (Tyler's decision,
  2026-10-04, following the no-left-bars rule). In `src/styles.css`, delete
  `.ws-row.active { box-shadow: inset 2px 0 var(--accent); background: #17251f; }`
  (line 932) and give the earlier `.ws-row.active` rule (line 257, today
  `background: var(--panel-2)`) a 1px `var(--line)` border. Give `.ws-row` a
  1px transparent border so rows don't shift when selected. The selected row is
  then `panel-2` with a hairline border, like a selected tab. No accent colour
  on the row.

### 1.2 Ask before quitting while agents are running

Today `RunEvent::Exit` kills every PTY (`src-tauri/src/lib.rs:846`) and nothing
handles a close or quit request first.

- Native: handle `WindowEvent::CloseRequested` (call `prevent_close`) and
  `RunEvent::ExitRequested { code: None, .. }` (call `prevent_exit`); emit a
  `quit-requested` event to the window. A new `quit_app` command sets a
  confirmed flag and exits; with the flag set, neither handler prevents.
- If the window hasn't answered within 2 seconds of `quit-requested`, let the
  quit through. Never block an exit with a code (logout, shutdown, update).
- Frontend: a pure `quitQuestion(busy)` beside `closeNeedsConfirm` in
  `src/closing.ts`. It returns `null` (quit at once) unless an agent terminal has
  not exited, a plain shell is working or waiting, or a thread is replying or
  waiting on a card.
  - Title: "<n> agents are still running." or, when exactly one thing is
    running and it is waiting, "<name> is waiting for you."
  - Body: "Quitting ends them and anything they're running. Threads and their
    messages are saved; replies in progress are not."
  - Up to 5 rows, e.g. "Codex · apex-deck · Working", "Null in Fix login ·
    apex-deck · Waiting for you", then "and 2 more".
  - Buttons: Cancel (focused) and "Quit and end them" (danger).
- `ChatPane` reports `ThreadStatus` (above) so `App` knows which threads are
  replying or waiting.
- The browser preview ignores quitting (no native window).

### 1.3 Centre the section tabs

Today the Agents / Code / Threads tabs follow the brand at the left of the title
bar (`.section-navigation { margin-left: 20px }`, `src/styles.css:136`; markup
`src/App.tsx:563-575`). Tyler asked for them centred (2026-10-04).

- The tabs sit at the centre of the title bar in every section. They don't move
  when the attention button appears, grows or goes away, or when the right-hand
  controls change by section (Agents shows "+ New agent" and no details toggle).
- The title bar becomes three groups: `.titlebar-start` (sidebar toggle, brand,
  preview badge, then the attention button pushed to the end of the group so it
  sits just left of the tabs), the tabs, and `.titlebar-end` (Providers, layout
  presets, the primary button and the details toggle, right-aligned). The
  title bar's `.spacer` goes away.
- `.titlebar-start` and `.titlebar-end` are each `flex: 1 1 0` with
  `min-width: max-content`, so the tabs are exactly centred whenever both sides
  fit, and shift aside instead of overlapping when one doesn't.
- The attention button moves from the right of the tabs to their left because
  the left side has the room: at 1280px both sides still fit with the longest
  label ("1 needs you · 1 failed · 1 ready"). It still sits beside the tabs and
  grows away from them, so neither the tabs nor the right-hand controls move.
- `.section-navigation` loses its `margin-left` at full width.
- At 1050px and narrower the groups stop growing (`flex: none`, with
  `.titlebar-end` keeping `margin-left: auto`) and the tabs follow the brand as
  today. At 720px and narrower they keep their own full-width centred row.
  Update the selectors that use `.titlebar > …` today (`styles.css:959`,
  `:962`, `:967`, `:970`, `:1857`) to the new groups.
- The attention list still opens below its button (`.attention-list`, `left: 0`).

## Stage 2: attention

### 2.1 Blocked approvals stay flagged until you answer

Today only a terminal's `needs_input` survives being looked at
(`src/App.tsx:357`, `:382`). A thread whose bot is stopped on a card loses its
flag and its ⌘J spot when you glance at it, and each new card overwrites the
note and resets "ago".

- `src/approvals.ts`: app-wide store of open cards per room, fed by `hub.ts`
  from `approval_requested` and `approval_resolved` (every card resolves,
  including on Stop and drop).
- Pure `approvalSignal(cards, names, now)` returns the flag for a thread from its
  oldest open card: note "Null wants approval: Run npm test · +1 more" (the
  "+n more" only when n ≥ 1), `at` = the oldest card's arrival, `blocking: true`.
  No cards → `null`.
- `ChatPane` signals from it on every request and resolution.
- `App`: a blocking signal is never dropped or cleared by watching; it clears
  only when its last card resolves. Watching still suppresses the dock bounce.
  "Asked you a question" stays non-blocking.
- Codex MCP hook calls carry `expires_at` (the hook denies after 570 s). Cards and
  list rows from such calls add "Denied automatically in 6m" (whole minutes,
  rounded up). Claude `can_use_tool` and Codex `requestApproval` never show a
  deadline.

### 2.2 Answer routine approvals from the attention list

- A thread row with open cards expands into an answer strip for its oldest card.
  - Command: kind label "Wants to run a command", the full command in mono,
    **Allow once** (primary), **Deny** (danger outline), **Open thread**
    (ghost).
  - File edit with 20 changed lines or fewer: "+8 −2 · src/auth/session.ts" and
    the whole diff, same three buttons.
  - Larger edit, MCP tool call or generic permission: only **Open to answer**.
  - Never **Always allow** in the list.
  - A muted line names the next card in that thread, e.g. "Next in this thread:
    Edit src/auth/session.ts · +8 −2".
- Answering calls `roomDecide(room, request, approve, false)`. The list stays
  open and focus moves to the next card; with none left, the strip reads "No
  approvals waiting".
- Terminal rows behave as today. The list widens from 380px to 440px.

### 2.3 Ready flags and the dock badge

- Footer: "Most urgent first · Mark ready as seen · ⌘J next". **Mark ready as
  seen** (ghost small) appears only while a Ready flag exists; it clears every
  `done` signal and leaves Needs you and Failed alone.
- The dock badge counts only Needs you and Failed. Ready still shows in the
  title bar and rail.

### 2.4 Escalate an approval left waiting

- When a blocking signal has been open for 2 minutes and the window doesn't have
  focus, request Critical user attention once for that card, never again for it.
- Ready flags and terminal flags never escalate. No notification plugin.

### 2.5 Pane heads say what is happening

- Pure `headLine(...)` in `src/composerStatus.ts` builds `ThreadStatus.text`
  when no flag shows:
  - one bot working: "Null · Running: npm test · 1m 12s"
  - two or more: "2 replying · Null: Editing src/App.tsx"
  - otherwise today's text ("2 bots").
- Command-line bots only: after 5 minutes with nothing heard (time with an open
  card doesn't count), the head and working line read "Quiet 6m · stops at 15m"
  in muted text.
- Terminal heads read "Working 4m", timed from a run start that `TerminalPane`
  reports.
- Uses `App`'s existing one-second tick. No new Stop button.

## Stage 3: conversation

### 3.1 Hold your place while bots stream

Today the transcript jumps to the bottom on every change (`src/ChatPane.tsx:650`).

- Auto-scroll only when you were at the bottom (within 80px) before the update.
- Otherwise keep your place and show centred pills above the composer (neutral
  panel, hairline border, pill radius, 12px):
  - "3 new · Jump to latest"
  - when an approval card is out of view: amber dot + "Null is waiting for you
    · Show". Show scrolls the card into view and focuses its Allow once.
- Composer status splits by state: "Jigga is replying · Null is waiting for
  you". Stop names only bots that are replying: "Stop Jigga".
- Saved `lastSeenSeq?: number` on chat panes, updated while the thread is
  watched and scrolled to the bottom. On return, a hairline uncoloured divider
  "New since you looked" sits above the first unseen message and the transcript
  opens there. It clears when you send. Older session files load without it.

### 3.2 Always show who gets your message

- A recipient line above the textarea whenever the thread has a bot, from the
  existing `roomTargets` call (ignore stale responses). Reasons:
  "To Null · you mentioned", "To Null · last addressed", "To Jigga · first in
  the room", "To everyone · everyone at once", "To Jigga, then Null · everyone
  in turn". While a target is busy add " · queued (busy)".
- The reason is a link (titled "Change who answers by default") that opens Room
  in thread details.
- Rename the policy option "Only who I @mention" to "Whoever I addressed last".
- 11px muted; hidden below 260px pane height.
- Empty room with bots: three example rows built from real handles, "e.g. @all
  what would you change first?", "e.g. @null review the last commit",
  "e.g. /pin Use pnpm, not npm". Clicking inserts the text without "e.g." and
  never sends.
- Before the first message in a room with 2 or more bots, the hint reads "@all
  asks everyone · / for commands · ↵ send".

### 3.3 Try again, and let a cut-off bot answer

- A failure notice whose bot is still in the room gets a ghost small **Try
  again** (not for storage errors). It runs that bot once on the transcript as
  it is (`roomTurn`) and reposts nothing.
- `HopLimitReached` carries `next: Vec<ParticipantId>`. The notice reads
  "Stopped after 3 rounds of models answering each other. Jigga asked Null
  next." with **Let Null answer** (or **Let them answer** for several).
  `room_turn` takes a hop budget; the button passes 0 so it buys exactly one
  reply.
- Buttons disable while that bot works and disappear once used or once you send.

### 3.4 Hand a quoted reply to another bot

- If your text already has an @mention, quoting doesn't prepend the quoted
  bot's handle.
- The quote preview shows "Quoting Jigga" and a **Send to Null ▾** menu listing
  the other bots and Everyone; it sets the leading handle.
- **Copy** beside Quote and Fork on replies; it copies the markdown and reads
  "Copied" for 1.5 s. Human messages get Quote and Copy too.
- While quoting, the placeholder reads "e.g. Check this against the tests and
  say what breaks".
- Below 360px pane width, message actions collapse into one ⋯.

## Stage 4: terminals

### 4.1 Names, the agent's own title and ⋯ menus

- Terminal pane heads use `ThreadName` (rename with double-click or F2).
- A second pane of the same tool in a workspace is numbered: "Codex 2".
- Subscribe to xterm's `onTitleChange`; keep a sanitised program title (strip
  leading non-letters and spinner frames, cap at 60 characters, at most 4
  updates per second, text only). Show it muted after the name: "Codex · Writing
  tests for auth" in the pane head, rail row and attention row.
- Terminal ⋯ menu: **Rename**, **Start again** (disabled while running),
  **Copy folder path**, separator, **Close** (still asks when busy).
- Thread ⋯ menu: **Rename**, **Fork**, **Export**, separator, **Delete
  thread…**.

### 4.2 Start again, and restore after a restart

- On exit the pane stays with its scrollback. A bar at the foot reads "Exited
  with code 1 · 14:02" with **Start Codex again** (primary) and **Close**. A
  non-zero exit flags Failed with "Failed · exited with code 1"; a clean exit
  gets the bar and no flag.
- Start again respawns in the same xterm under a fresh PTY id
  (`<pane id>:<generation>`) and writes a dim "— started again 14:05 —" line.
- Terminal descriptors and the Code layouts are saved beside threads. On launch
  terminals come back **Stopped**, never started: body "Codex stopped when Apex
  Deck quit. Earlier output isn't kept." with **Start Codex** and **Close**.
  A tool that is no longer installed shows "Codex isn't installed" and Start is
  disabled.
- Saved layouts drop ids that didn't load.
- Deferred: "Start all", resume flags such as `--continue`.

## Stage 5: trust and review

### 5.1 Say what Always allow covers, and make Remove take it back

- `ProposedAction.risky: bool`, set from `mcp::needs_approval` or Codex
  `riskLevel: "high"`. The card's kind label adds " · can spend money or
  publish".
- Risky cards replace "Nothing happens until you choose." with an always-visible
  scope line: "Always allow lets Null call x-mcp: post_tweet in this thread with
  any arguments, without asking." Other cards show their scope line ("Always
  allow lets Jigga run this exact command in this thread without asking.") on
  hover or focus of Always allow. No extra confirm step (c259fac put Always
  allow on every card on purpose).
- Codex: send persist `session` instead of `always`, and answer silent rule
  matches with a plain accept, so Deck's saved list is the only lasting record
  and Remove really takes it back. Match Codex command rules on the command
  alone, not its reason text.
- `AllowedRule.allowed_at` (serde default). Rows read "Allowed Oct 4" plus
  " · can spend money or publish" for risky rules. After Remove: "Removed. Null
  asks again next time."
- Fix the stale comment at `crates/apex-core/src/approval.rs:84` and the README
  section on Always allow.

### 5.2 Battery colours and saved token totals

- Low battery cells draw in the agent's own colour with a hairline outline.
  Critical gets a thicker outline and the word "low". No `--danger`, no red
  pulse.
- Each bot's token totals are saved on the room snapshot (serde default) and the
  usage card says "in this thread".

### 5.3 Send the change to a reviewer

- **Ask for review ▾** in the Changes head opens a menu: a scope line "Since this
  thread started · 6 files · +73 −16", then the thread's bots, read-only first;
  bots that can edit carry a muted "Can edit files".
- Picking one joins the patches Changes shows into one file, saves it with
  `saveAttachment` as `review-since-start-<n>.patch`, and fills the composer with
  "@ada Review this change." plus the standard "Attached file: <path>" line. It
  never sends.
- Over 2,000 lines: show the size and offer "One file per patch".
- Check that Codex and custom command-line bots can read the attachments folder;
  if one can't, say so in its row ("Can't read attachments").
