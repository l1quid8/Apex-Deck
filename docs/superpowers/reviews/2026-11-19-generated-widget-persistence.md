## What changed

- `window.generatedUI.widgetState` returns a detached snapshot before generated JS starts. `setWidgetState(value)` validates and updates that local snapshot synchronously; changes are coalesced over 100 ms before host delivery. The existing immutable `generatedUI.discuss` remains separate and unchanged.
- JSON only: 4,096 UTF-8 bytes, depth 16, 512 values; finite numbers, dense arrays, plain data objects. Rejects functions, undefined, BigInt, accessors, cycles, nonfinite numbers, exotic prototypes and named array properties. Wrapper and main repeat validation. Messages bind run ID and revision digest, have exact keys, and retain existing flood limits.
- Main owns the new `WidgetStore` subsystem in `<Electron userData>/generated-widgets/widgets.json`. The digest binds host, thread, message sequence, card ID, complete card payload and adapter/security versions. A different identity or code revision starts fresh. Saves from removed runs cannot enter the store.
- Settings and images survive orderly app restarts through atomic private local files (directory 0700, file 0600). This is a bounded cache: up to 128 revisions and 16 MiB total; image pressure evicts older images before settings. Abnormal termination may lose a pending disk write. No cloud sync or merge across simultaneous app processes is provided.
- The native generated view alone is sampled every 750 ms and at teardown. No Deck page, draft, browser view or other app is captured. PNGs are reduced if needed to stay under 1 MiB each. Final capture is best effort; a cached image can lag the last interaction. Raster data goes only to the owning trusted Deck frame and cache lookup accepts validated card identity/source, never a path.
- The native surface stays hidden during bootstrap and is revealed on ready, so its blank wrapper does not cover cached pixels. Desktop reserves blank space before first render/cache lookup, then retains cached pixels during safe teardown/remount instead of flashing fallback text. Historical/offline cards can read their own cached image without execution authority. Unsupported phone clients and invalid/unavailable cards without an image retain readable fallback.
- Existing offscreen/overlay/blur/revision disposal, geometry lease, watchdog, permission and network policy stay in place. A final bounded (100 ms) read of the original sealed snapshot before renderer termination closes the immediate-click-then-scroll IPC race. Disposed child messages remain rejected; this fixed host-owned pull reads only that original card's state.
- Renderer accepts a final host-produced raster from its latest run even after disposal; no actions or execution authority are accepted from that event. Stale mounts/revisions cannot update the new card.
- Bot guidance and calculator/chart examples restore validated saved fields, save meaningful changes, and persist Reset defaults. Existing generated replies must be regenerated/updated to use the bridge: arbitrary old JavaScript cannot have its private variables inferred. Built-in flowchart/scale/bars formats are unchanged.
- Adapter bumped to `open-intelligent-ui-8391a94-deck-3` with the matching existing Darwin arm64 / Electron 44.5.1 / Chromium 152.0.7977.130 tuple in the registry. This is an unmerged change requiring review, not a new production release claim.

## Integration review

Fresh TypeScript and all 124 focused tests pass; `git diff --check` passes. A different-model read-only review found two P1 merge blockers:

1. `shared/generated-ui-runtime.json` carries production approval into adapter deck-3 without candidate-matched production-chat and external-capture receipts. Do not merge that approval until those checks pass; alternatively, clear the verified runtime list for a disabled integration.
2. `desktop/generated-ui/host.mjs` reads `window.generatedUI.widgetState` through child-world `executeJavaScript` during teardown. The result crosses into Electron main before its size is validated. Child-world serialization intrinsics are mutable, so the sealed getter does not establish a bounded envelope. Replace this final pull with a bounded trusted-wrapper flush/ack path and rerun immediate-teardown persistence and hostile-state probes.

These findings mean the earlier focused/probe passes are insufficient for merge. The existing production-chat and external packet-capture gaps remain open. Main and the installed app are unchanged by this integration attempt.
