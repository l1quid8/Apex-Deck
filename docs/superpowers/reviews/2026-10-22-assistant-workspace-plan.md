# Assistant workspace plan review

Scope: design and plan publication only, with a browser-local mockup. Production changes, merge, installation and release are not included.

A fresh read-only reviewer compared the spec and implementation plan for assistant/project ownership, cross-host identity, legacy preservation, explicit approvals and restart recovery. These align. The reviewer found an ambiguous memory-promotion deduplication key; the final plan now keys promotion by project/task/attempt/scratchId, independently of retry request IDs.

The latest direction removes the cosmetic Team Member Type selector and the proposed type-label field. Users name assistants and give work briefs in Conversation; every assistant can coordinate reusable workers across assigned projects. Existing legacy labels/metadata remain stored without a destructive migration. The original production Agents tab remains the reusable-worker manager; Your team and + manage assistants. Avatar creation and Settings retain pixel patterns, palette colors and a custom color picker with an editable hex value.
